# ペン入力・手振れ補正 品質改善プラン

## 目的

手振れ補正を有効にすると線は多少滑らかになるものの、細い線や曲線に残る「かくつき」「シャギー感」を解消する。

単純に補正を強くするのではなく、次の要素を分離して改善する。

1. OS / タブレットから届く入力点の取り込み
2. 手振れ補正の速度判定と平滑化
3. 入力点の間隔を揃えるリサンプリング
4. 曲線補間
5. ライブ描画末尾の安定性
6. 4x サブピクセル描画の座標整合

## 現行仕様との関係

AI Cortex の現行仕様では、ペンエンジンは次を前提としている。

- PointerEvent から float 座標・筆圧・傾きを取得する
- CPU 側でサンプリングレートのばらつきを吸収する
- EMA + 速度連動で手振れ補正する
- Catmull–Rom スプラインで補間する
- 4x サブピクセルバッファをダウンサンプルして描画する
- 高速時の先端予測は、末尾1区間だけ仮描画して実点到着時に差し替える

本計画はこの方針を維持し、不足している入力処理と描画上の不安定要因を段階的に解消する。

### 2026-07-29 Kamox確認結果

Kamox v0.1.11 のElectronモードでPhotonMixerを起動し、標準マウスAPIから同じS字＋微小ジッター入力を再生した。

- 対象プロジェクト: `photon-mixer`
- ウィンドウ: `PhotonMixer Phase 1`
- キャンバス: 800×600
- ブラシ: 円形、4px、不透明度100%、にじみ0%
- 比較: 補正0% / 100%
- 実行時表示: 120 FPS、Latency 0 ms
- Kamox `check-ui` のアプリエラー: なし
- スクリーンショット: `.kamox/screenshots/electron_1785311607491.png`

画面上では上段が補正0%、下段が補正100%。

観察結果:

- 補正100%では微小な揺れだけでなく、意図したS字の振幅まで大きく減衰した
- 補正100%の終端は入力したペン位置まで届かず、かなり手前で止まった
- 補正0%でもCatmull–Rom補間により点間は連続しているが、入力点の影響がそのまま曲率へ残る
- 補正を強くしても、細線輪郭のシャギー感を根本的に消す処理にはなっていない
- 現状の補正は「形を保ったまま高周波のブレだけを除く」のではなく、ストローク全体を低域化して振幅と終端も失わせている

この結果から、Phase 2では終端処理も明示的な完了条件に含める。ペンアップ時には最後の生入力位置へ自然に収束させるか、遅延分を限定した終端補間を行い、補正済みストロークが途中で切れたように見えないことを検証する。

## Phase 1: 高密度入力の取り込み

### 変更

- `pointermove` の `getCoalescedEvents()` を読み取る
- まとめられた中間点を発生順に入力列へ追加する
- 各点の `timeStamp`、筆圧、傾き、float 座標を保持する
- coalesced event が利用できない環境では通常イベントへフォールバックする
- 同一時刻・同一座標の重複点を安全に処理する

### ねらい

現在捨てている可能性があるタブレットの中間点を取り込み、補間前の元データを滑らかにする。

### 完了条件

- 1回の `pointermove` に複数点が含まれる場合、全点を順番どおり取得できる
- 筆圧と傾きが各点で保持される
- マウス入力と既存のタッチ除外を壊さない

## Phase 2: 手振れ補正の速度計算

### 変更

- 速度計算用の直前生入力点と、EMAの直前出力点を分離する
- 速度は生入力点同士から計算する
- サンプル間隔に依存しにくい時間ベースのEMAへ変更する
- 補正0%は入力を変えない
- UIの0〜100%という意味は維持する
- AI Cortex の式との差を解消するか、意図的に異なるカーブを採用する場合は仕様更新候補として提示する

### ねらい

補正による遅れを高速移動と誤認して補正が急に弱くなるフィードバックをなくす。

### 完了条件

- 同じ軌跡を60Hz相当と240Hz相当で入力しても、出力形状が大きく変わらない
- 補正を強くするほど高周波のブレ量が単調に減る
- 0%では位置が変化しない
- 100%でも極端な追従遅れや終端の取り残しが発生しない

## Phase 3: 弧長リサンプリング

### 変更

- 補正後の点列を、曲線補間前に一定距離間隔へ並べ直す
- 区間をまたいだ余り距離を保持し、点密度を均一にする
- 筆圧・傾き・時刻も区間内で補間する
- 入力点数ではなく移動距離を基準に出力点を生成する

### ねらい

イベント間隔やペン速度による点密度のムラを、曲線形状やスタンプ濃度へ持ち込まない。

### 完了条件

- 出力点間隔が設定値の許容範囲に収まる
- 入力イベント間隔を変えても同じ軌跡からほぼ同じ点列が得られる
- 区間境界に2倍間隔の隙間が発生しない

## Phase 4: 安定した曲線補間

### 変更

- 一様Catmull–Romをcentripetal Catmull–Romへ変更する
- 始点・終点の接線を明示的に扱う
- 同一点や極端に短い区間でNaNやオーバーシュートを発生させない
- 補間とスタンプ配置の責務を分離する

### ねらい

不均一な入力や小さな折り返しで発生する膨らみ、うねり、曲率の急変を減らす。

### 完了条件

- 直線入力が直線のまま保たれる
- 小さな円とS字でループや不自然な膨らみが出ない
- 補間点が入力点列の局所的な範囲から大きく逸脱しない

## Phase 5: ライブ描画末尾の分離

### 変更

- ストロークを確定済み区間と可変な末尾区間に分ける
- 新しい入力点が来ても確定済み区間を作り直さない
- 末尾1区間だけを仮描画し、次の実点到着時に差し替える
- 先端予測はこの構造が安定してから有効化する

### ねらい

入力点が追加されるたびに直前の線が微妙に動く現象を防ぎ、ペン先付近の表示を安定させる。

### 完了条件

- 新しい点の到着で確定済み区間の形が変わらない
- ライブ表示からペンアップ確定時に線が跳ねない
- Undo / Redoの1ストローク単位を維持する

## Phase 6: 4x サブピクセル描画の整列

### 変更

- 4x bboxの開始位置を4の倍数へ外向きに切り下げる
- 終了位置を4の倍数へ外向きに切り上げる
- 1x書き込み先との対応を整数座標で保証する
- キャンバス端でのクリップ後も、最低サイズと4倍整列を維持する
- bbox再確保の頻度とライブ描画性能を計測する

### ねらい

4xサンプルの位相ずれによる輪郭のギザギザ、濃淡の揺れ、位置依存のエッジ品質差を防ぐ。

### 完了条件

- bbox原点とサイズが常に4の倍数
- 整数位置と小数位置で同等のアンチエイリアス品質になる
- ライブ表示と確定後で輪郭が変化しない
- キャンバス端のストロークでWebGPU validation errorが出ない

## 実装順とコミット境界

1. 高密度入力取得と入力テスト
2. 生入力速度・時間ベースEMAと補正テスト
3. 弧長リサンプリング
4. centripetal Catmull–Rom
5. ライブ末尾区間の分離
6. 4x bbox整列と画像比較

各段階で既存のUndo / Redo、混色、消しゴム、ぼかし、レイヤー描画を回帰確認する。問題が発生した場合に段階単位で原因を切り分けられるよう、まとめて1コミットにはしない。

## 2026-07-29 実装結果

Phase 1〜4とPhase 6、およびペンアップ終端補正を実装した。

- `getCoalescedEvents()`から中間入力点・各点の時刻・筆圧・傾きを取得
- 速度計算を生入力点同士へ変更
- 120Hzを基準にした時間ベースEMAへ変更
- AI Cortex記載どおり、速度比を`minAlpha`〜`maxAlpha`へclamp
- ペンアップ位置を入力列へ含め、確定時は最後の生入力位置へ収束
- Catmull–Rom前に2px間隔の弧長リサンプリングを追加
- 一様Catmull–Romをcentripetal Catmull–Romへ変更
- 4x bboxの原点・終端を1xピクセル境界へ外向きに整列
- キャンバス外のストロークも安全な最小bboxへクランプ

検証結果:

- `npm test`: 183 tests pass
- `npm run build`: pass
- Kamox: 40px半円ストロークで内外輪郭の区間的な平坦化・膨らみが減少
- Kamox: カーソル中心と確定ストローク終端が一致
- Kamox: アプリ / WebGPUエラーなし
- 修正後スクリーンショット: `.kamox/screenshots/electron_1785327655461.png`

Phase 5の「確定済み区間と可変末尾区間の描画分離」は未実装。今回の修正で確定線の形状と終端は改善したが、ライブ描画中に直前区間がわずかに更新される構造は残っている。先端予測を有効化する前に別工程として実施する。
